# Architecture

A deeper look at how the pieces fit together. The README has the overview; this file explains boundaries, data contracts, failure behaviour and security. Diagrams are generated by [`docs/diagrams/generate.py`](diagrams/generate.py).

## 1. Components and boundaries

| Component | File | Depends on | Notes |
|---|---|---|---|
| Label and constants | `risk_common.py` | NumPy | The only place the star-rating to tier mapping lives |
| Decision layer | `decision.py` | NumPy | Pure functions; every threshold comes from `decision_config.json`; no ML imports, so it is trivially testable |
| Classical model | `classical_model.pkl` via `hybrid_inference.py` | scikit-learn | TF-IDF (1 to 2 grams, 5,000 features) + scaled age and feedback count + one-hot division, department, class; Logistic Regression |
| Transformer | `transformer_assets/`, `compact_transformer.py` | PyTorch, Transformers | DistilBERT, max 128 tokens; weights stored per-row int8 with fp32 scales and de-quantised at load, which avoids any dependency on a CPU-specific quantisation engine |
| Explainer | `llm_explainer.py` | stdlib (Ollama via HTTP), boto3 (Bedrock) | Provider-switchable; never decides |
| API | `app.py` | FastAPI | Validation, auth, monitoring hook |
| Monitor | `monitoring.py` | stdlib | Rolling window plus CloudWatch EMF lines |

The dependency direction is one-way: `app` to `hybrid_inference` to (`decision`, models, `llm_explainer`). `decision` imports nothing heavy.

## 2. The data contract

Input fields are validated by Pydantic (`ComplaintInput`). Unknown fields are ignored, so older clients that still send `image` or `recommended_ind` keep working; neither is used. The response always contains `model_outputs` (decided deterministically), `llm_explanation` (always present after a successful prediction, from the LLM or the fallback) and `_meta.explanation_source` so a consumer can tell which.

`final_score` and the two `*_score` fields are display-only expected values (0 x P(low) + 0.5 x P(medium) + 1 x P(high)). Decisions use the probabilities.

## 3. Failure behaviour

| What fails | What happens |
|---|---|
| LLM provider down, timeout (60 s), or credentials missing | Local fallback explanation, still policy-correct; `explanation_source = "fallback"`; no retry on outage |
| LLM returns bad JSON, empty fields, a different risk tier, or invented numbers | One retry at temperature 0.5; if still bad, the fallback |
| LLM tries to change action or review flag | Ignored: both are overwritten from the decision layer. The LLM may only add caution |
| A model artifact is missing | HTTP 503 with a generic message (details stay in logs) |
| Anything else unexpected | HTTP 500 with a generic message |
| Task becomes unhealthy | The load balancer stops routing to it, ECS replaces it, an alarm fires |
| Many requests from one IP | WAF returns 403 until the rate window passes |

## 4. Security model

- **Perimeter.** CloudFront terminates TLS; WAF rate-limits per IP; the load balancer's security group admits only CloudFront's managed prefix list; tasks accept traffic only from the load balancer.
- **Authentication.** `X-API-Key` compared in constant time; the key is generated by Secrets Manager and injected as a secret environment variable.
- **Least privilege.** The task role may call `bedrock:InvokeModel` on one inference profile and its foundation model; the execution role reads one secret. The GitHub deploy role is assumable only by this repository's `production` environment and can pass only the stack's own roles to ECS.
- **Untrusted text.** Complaint text is treated as data end to end: length-capped, delimiter-stripped, and unable to reach the action or review flag.
- **Data minimisation.** No complaint text or identifiers in metrics or `/stats`; with Ollama, no text leaves the machine.

## 5. Observability

Each prediction prints one CloudWatch Embedded Metric Format line (namespace `HybridRiskApi`): `Predictions`, `ReviewRequired`, `FallbackExplanation`, `AutoReply`, `EscalatedHigh`, `TopProbability`. Averages of the 0/1 metrics are shares over any period. Alarms: load balancer 5xx, unhealthy target, fallback share above 40%, review share above 50%. `monitoring_baseline.json` records the test-split shares that `/stats` compares against.

## 6. Scaling and cost

One task is 2 vCPU and 4 GB; target-tracking autoscaling (CPU 60%) runs 1 to 3 tasks. A single prediction is dominated by the LLM call (about 6 s end to end with Bedrock); the two text models take well under a second on CPU. A running stack costs roughly 3 to 6 dollars a day, mostly the load balancer and Fargate; delete it when idle.

## 7. Replacing the proxy label with real outcomes

1. Change `rating_to_risk` (or add a loader in `make_splits.py`) so `risk_level` comes from your outcome column.
2. Rerun `make_splits.py`, both training scripts, `tune_decision.py` and `evaluate_hybrid.py`.
3. Re-check the review-trigger limits in `decision_config.json` against the new review share, and refresh `monitoring_baseline.json` (written by `evaluate_hybrid.py`).
